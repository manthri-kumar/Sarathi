# Feature-by-feature board review and journey traces

For each feature below: **Job** = A, **Entry/dependencies/evidence** = B/C/I, **Behavior/paths** = D/E, **Findings** = F/H, **Change/validation** = G/J, **Disposition** = K. Priority and complete fix specifications are canonical in [findings](05-findings.md). All runtime outcomes described here are code-derived unless report 09 names an executed check.

## F01–F03: access, identity and recovery

**F01 email access.** Job: understand the companion and create/recover a trustworthy account. Entry: `/`, `client/src/components/Auth/AuthPage.js:22,127,200`; dependencies: auth routes, User/Otp, Brevo (`server/routes/authRoutes.js:11–23`). Happy path sends code, verifies email, returns to login, stores seven-day JWT and enters Dashboard. Failure paths show alerts/inline OTP error and resend cooldown; no account/user bootstrap verification after storage. Mobile splash delays first access and hides marketing panel; Start Exploring is inert; autocomplete suppression makes password managers harder to use. A10/A11/A27/A29 cover verified bypass, attempt/replay deficiencies and inaccessible controls. Recommended smallest change: secure all creation paths, then improve existing form semantics and error/retry while retaining brand. Validate OTP expiry, failed delivery, repeat clicks, duplicate accounts, password-manager completion and 30-second comprehension. **Blocked, P1**; marketing polish can follow.

**F02 Google access.** Job: sign in with a proven Google identity. Entry: same page `:81–125`; Google access token is parsed from URL fragment and userinfo fetched, then only profile strings reach backend. Failure clears fragment and shows error. Backend success is unsafe even though browser userinfo fetch succeeds; A01 is **P0 blocked**. Verify server credential binding, wrong audience/issuer/expiry rejection and safe account linking; implicit flow/state/nonce choices need explicit review during remediation. Do not mistake a verified browser response for server verification.

**F03 password recovery.** Job: regain exclusive account control. Entry: login modal (`AuthPage.js:232–375`); dependencies: reset endpoints and Brevo. Happy path email → six digits → reset token → password/confirmation → login. Failure uses inline error and throttled resend; generated token remains reusable within expiry; previous JWT survives password change. A11/A09 **P1 blockers**. Validate cryptographic code, attempt caps, consumed nonce, stale-session rejection, email enumeration and concurrent use. Preserve the multi-step UI and focus convenience, add accessible announcements and explicit recovery of failed send.

## F04–F09: orientation and discovery

**F04 navigation/search/languages.** Job: find a destination or tool and move predictably. Entry: Sidebar/Navbar (`Sidebar.jsx:45–110`, `Navbar.jsx:22–122`), App routes, i18n. Search means feature-name routing on most screens and city selection on Explore; city hook debounces/aborts some requests. Arrow keys exist for Explore suggestions but result rows and non-Explore search lack full semantic navigation. Settings and Navbar logout point to absent routes; expired tokens don't trigger a shared recovery flow. Translation resources do not cover all visible text or referenced keys. A09/A27/A29 **block critical navigation**. Keep search context explicit; explain selected destination and locale; validate all routes from direct URL/back/reload, expired session, keyboard, en/te/hi and longest labels. Accessibility and translation completeness are not established merely by i18next.

**F05 Dashboard/GPS/actions/hero.** Job: get useful next steps immediately. Entry: `/dashboard`, `Dashboard.jsx:35–227,287–336`; Cards `:47–70`, Hero `:31–100`. Dependencies: local user/city, GPS, direct Google Geocoding, recommendations API. Happy path greets and resolves city, routes to three planners/chat/Explore; hero rotates with CTA. Failure often logs or alerts; indefinite “detecting” can remain after geocode/permission failure. Sensitive token/user logs and key literal A12; permission/manual alternative A15; inconsistent planner jobs A29. **Not certified, security blocked**. Remove sensitive diagnostics, make manual destination available and explain location use; validate no-permission startup, stale stored coords, no geolocation, slow geocode, usable first step in 30 seconds. Carousel motion/pause/readability needs browser review.

**F06 popular destinations.** Job: get inspiration before choosing a destination. Entry: Dashboard PlacesSection; exact evidence `PlacesSection.jsx:94–140,286–369`. Static cards open a modal with destination descriptions and Maps navigation. Missing props default to curated data, but the same fallback for empty real results is unsafe (A16). Rating/review numbers and some metadata lack provenance (A17). Escape/scroll cleanup/role/name are implemented for popular modal; focus trap/restore not shown. **Blocked until factual labels/empty behavior fixed; P2 modal usability**. Keep curated inspiration visibly distinct from near-me businesses; validate missing/zero metadata, unrelated image fallback, destination-vs-business wording and keyboard modal lifecycle.

**F07 recommendations.** Job: find relevant nearby options. Entry: Dashboard RecommendedPlaces (`:120–159,190–207,219–228`); dependency: recommendationController. Fetch cancels on coordinate change/unmount, handles errors/skeletons; empty hides the section. Hearts affect only state, Explore button opens external directions, desktop slides differ from mobile first-four slice. “For You” uses location, not preferences; provider caps defeat 150km coverage claim. A05/A17/A33. **Not ready for durable-save/personalized claims**. Preserve cancellation, show truthful scope/unknowns, connect one save store and show navigational consequence. Validate refresh save, last page after location change, GPS unavailable/zero, mobile View All, radius/source metadata and provider quotas.

**F08 Explore places/restaurants/hotels.** Job: discover useful options near home or a future city without mandatory GPS. Entry: `/explore`, `Explore.jsx:145–308,339–517`; dependencies: Places aggregation, geocode, shared city context. GPS happy path populates three lists; city selection triggers Places/food fetch. Failure can log only or produce empty arrays; one provider failure collapses aggregate. Selected city doesn't unlock results on fresh/GPS-denied state; empty businesses can display default tourism cards. A15/A16/A18 **P1 blockers**. Separate permission from selected destination/results, normalize body statuses, show partial results and retry per category, reject stale responses. Test denied GPS + city selection, city A/B races, fresh/reload state, category emptiness and quota/auth failure. Hotel discovery is lookup only—no availability, booking, date-specific quote or reservation behavior discovered.

**F09 dishes and restaurant matching.** Job: learn what to eat and find a plausible real business. Entry: FoodSection (`:44–123`); backend foodController `:106–156`; image/place services. Happy path generates dishes then concurrently enriches images/businesses; allSettled prevents one failed dish from failing entire enrichment. Missing image gets neutral placeholder, missing place gets no-result text, directions include Place ID. Entire food request waits for enrichment, and UI often renders generic empty on failure. A23 relevance/provenance **P2**, A13/A18 cost/deadline **P1**. Keep honest placeholders and identity-based directions; label “suggested place” until menu evidence, cap lookups and preserve source links. Validate dish/restaurant city, unrelated candidates, image license/credit, quota timeout and partial enrichment. Five mocked image assertions passed; real dish authenticity/menu/image match is **not verified**.

## F10–F16: planning and returning users

**F10 manual itinerary builder/optimizer.** Job: select known places and arrange a feasible visit. Entry: `/itinerary`, `Itinerary.jsx:276–399`; search/detail APIs and optimizer. Happy path: destination/filter search, detail/notes, add/remove selected Place IDs, dates/travelers, generate schedule and map. Search errors have text/skeleton states; modal reads JSON even for HTTP errors; generic placeholders may become fake facts. Optimizer drops unreachable places and repeats slots; filter selection requires another Search; dates/metadata aren't fully restored. A07/A08/A13/A17/A27. **Blocked P1**. Preserve selected-place control and nearest-neighbor heuristic only as an explicitly limited suggestion; validate place-set equality, semantic details, date/time/travel feasibility, stale plan changes after generation, keyboard interaction and map unknowns. No evidence supports “AI” for this deterministic endpoint.

**F11 template/draft/confirmation.** Job: trust that saved planning work survives and can be resumed. Entry: Itinerary `:403–423,793–801`; dependencies: local sarathiPlan, notifications, Mongo Trip. Template button only notifies; automatic local storage holds selected places, not named templates/full metadata. Confirm sends incompatible generated response, ignores status and clears draft. Happy-path promise is not met by current contracts; A03/A04/A05 **P1 blocked**. Define complete trip/save DTO and a verified persistence acknowledgement; retain local recovery until success; restore/reopen by ID. Validate full field equality, failed/uncertain writes, idempotent retry and session expiry. “Draft saved” must mean a retrievable draft, not just a notification.

**F12 Day Planner.** Job: quickly organize nearby activities for today. Entry `/day-planner`, DayPlanner `:15–73`; controller `:5–100`. Happy path fetches GPS and first four matches for selected interest; directions use coordinates. Unsupported/denied location blocks; server error can replace result silently; Generate stays enabled; no date/hours/break/route constraints, all four suggestions share one interest, cost fixed ₹300; no durable save. Missing mobile shell wiring A26. **Blocked for trustworthy day-plan promise, P1/P2**. Add manual location, visible error, bounded input and honest proposed-order/estimate semantics; reuse canonical plan/save. Test permission denied, <4 matches, null slot, provider error, duplicate generation, practical feasibility and mobile return navigation.

**F13 budget Trip Planner.** Job: decide whether a trip is affordable. Entry `/trip-planner`, TripPlanner `:8–41`; controller `:5–127`. Happy path converts form strings, finds one page of attractions, applies fixed rates, displays three places/day and remaining budget. No origin/date input; transport quote cannot reflect route; no schema bounds; hotel uses days rather than explicit nights; negative budget remaining is green; HTTP errors lack user-facing handling. No save/resume button; no LLM. A08/A13/A14/A18/A26/A29. **Blocked P1**. Keep simple estimator as an honest mode, share assumptions/canonical arithmetic and selected trip lifecycle. Validate invalid/huge inputs, zero availability, destination disambiguation, over-budget message, currency/units and same inputs across chat/manual planner.

**F14 My Trips.** Job: return to, adjust or remove a saved journey. Entry `/my-trips`, MyTrips `:17–77,80–174`; Mongo trips. Correctly accepts `{trips}` or array; unexpected shape produces retry instead of rendering .map on object. Error text distinguishes 401/403; edit/delete cannot match backend; saving to Saved is local; no complete itinerary reopen display; name-only navigation can resolve wrong place. A03/A05/A06. **Blocked P1**. Retain list validation/retry, add complete detail/resume and owner-scoped management. Test empty/load/error, valid wrappers, malformed list, expired token, update/delete success/failure, two-user isolation and Place-ID navigation.

**F15 Saved Trips.** Job: retrieve favorites/templates consistently. Entry `/saved`, Saved `:11–46`; only per-user local storage, not SavedTrip model. Happy path lists locally saved My Trips and removes item; malformed JSON/wrong shape can crash because parsing is unguarded and no top-level boundary is mounted. Temple/recommendation/template saves won't appear. A05/A09/A17. **Blocked P1 for unified-save promise**. Use canonical collection or clearly scoped local-only mode; non-destructive import/repair, typed records and ownership checks. Validate corrupt/quota storage, switch accounts, logout/relogin, another browser, empty state CTA and deletion error.

**F16 Profile/account.** Job: see accurate account data and manage supported personal details. Entry `/profile`, Profile `:23–83,128–133,286–301`; local user and server counters. Happy path displays identity, opens local edit and writes local JSON; trips wrapper makes count wrong; Saved counter differs from local UI; hardcoded verification/activity status; no server account-edit/delete endpoint. A25/A05/A09. **Not ready as account management**. Persist permitted fields through authenticated contract, verify email changes, remove unsupported claims; decide consent/retention/delete workflow before launch (A30/A12 privacy scope). Test cross-device identity, counts, reauth, duplicates, invalid input, global menu synchronization and deletion lifecycle.

## F17–F23: cultural guide and AI

**F17 Temple Discovery.** Job: identify a real temple and choose a visit. Entry `/temples`, TempleExplorer `:190–310`; mounted nearby/search routes. Happy path GPS → temples; city/name search works independently of backend browser-location bias; filters open/top-rated; details/Maps/AskAI. No results and denied location have clear text, but unsupported geolocation can throw and concurrent nearby/search can overwrite choice. Local-ID heart is not Saved; endpoint base defaults localhost; radius/paging bounded inconsistently. A05/A15/A18/A27. **Blocked by security/config/save gaps; strong foundation**. Keep actual Place IDs and city fallback; validate same-name temples, permission denial, manual search race, zero coords, radius bounds, refresh and focusable cards.

**F18 Temple Overview.** Job: confidently know hours, contact and visit requirements. Entry `/temples/:placeId`, TempleDetailsPage `:70–123`, OverviewTab `:6–130`; Places details then Wikipedia/Gemini enrichment. Base details can render before enrichment; Google failure shows back action; enrichment fails non-fatally but error prop is ignored by OverviewTab, so missing practical content has little explanation. Generated darshan facts are displayed beside Places facts without distinct evidence. Local error boundary displays raw stack. A18/A21/A27. **Not verified for practical accuracy; blocked definitive claims**. Keep independently rendered base details, validate enrichment shapes, source/time dynamic facts and offer unknown/official-contact fallback. Test quota, malformed nested JSON, fast temple A→B changes, stale responses, null hours, safe website/contact links and mobile deep link.

**F19 History/Rituals/Festivals.** Job: understand the cultural context while respecting uncertainty and tradition. Entry: six-tab details page, active `/enriched` branch (`templeController.js:380–442`), HistoryTab/RitualsTab/FestivalsTab. History uses Wikipedia-only sections, facts/timeline, links and empty state; ritual/festival source strings and fallback/contact guidance exist. Content identity is scored, not externally verified; first timeline item becomes Established; labels claim official sources broader than pipeline; section extractor used by chat expects wiki headings while retrieval gives plain headings. A22/A20 **P2**, identity/accuracy **P1 risk**. Keep source-only behavior, distinguish legends from dates/history and actual from inferred facts. Validate ambiguous names/coords, missing source/section, renovation vs founding, long Telugu names, source links and no-data readability.

**F20 Videos.** Job: preview the selected temple. Entry Videos tab → lazy fetch, VideosTab external YouTube fallback. Empty youtubeService makes active endpoint fail. A19 **P2 blocker if retained**. Choose working bounded provider integration or explicit external search; remove diagnostic infrastructure guesses from user empty state. Validate selected temple identity, no results vs outage/quota, keyboard playback and safe external link.

**F21 Travel Guide/services.** Job: get to the temple and locate nearby essentials. Entry Travel tab, TempleDetailsPage `:145–162`, TravelGuideTab `:4–130`; Places around temple coords, model-generated airport/rail/bus/directions/accessibility. Three service categories requested concurrently and each failure returns empty; no explicit failed-category state. Map reflects temple coords; supports hotels/restaurants/parking, not all README categories. Unknown accessibility becomes not available. A21/A18/A22. **Not certified; physical-access claims blocked**. Preserve destination anchoring/Place-ID links; show unknown accessibility, source verified practical facts and partial errors. Validate service-anchor coordinates, empty/failed categories, wrong-city airport, wheelchair unknown/true/false and route handoff.

**F22 General AI/chat planner/weather/transport.** Job: ask useful follow-ups and build a budget-aware trip conversationally. Entry Dashboard Chat or Temple Discovery general AI, ChatPanel `:107–294`; chat routes/state machine, ConversationService, ContextService, Budget/Transport/Train/TripPlanner services. Happy paths include nearby cards, live-provider weather attempt, date/time, multi-step transport/hotel/budget summary, confirm itinerary and over-budget options. Input disabled while typing, abort/retry exists. Failure can become generic text; reset ignores HTTP status; no durable trip save; caller-controlled sessions; partial typed history; generic guides preempt entity follow-ups; route cache survives destination edits; car costs multiply group total; weather label can use city context with unrelated GPS. A02/A14/A20/A21. **Blocked**. Test all planner states, edits/cancel/restart, close/reopen/reset, unrelated questions, greetings, named entities, GPS-denied fallback, current vs destination weather, cost scope and provider faults. Validate Open-Meteo variables against current contract before claiming live weather support; not exercised here.

**F23 Temple AI.** Job: ask about the chosen temple with sourced context. Entry temple card AskAI/details floating button → `/api/temples/chat` (`templeController.js:496–561`). Retrieves wiki per request and builds a temple-specific prompt; Groq then Gemini fallback; both failed gives 503. Client sends only current message/context, no prior conversation; details page omits available rating/enrichment in chatContext. Prompt rules alone do not prevent injection; no type/length bounds and practical facts may come from caller. A13/A21/A22. **Not verified, safety/provenance blocked**. Preserve bounded retrieved context, validate and separate data from instructions, add server-owned selected identity and explicit conversation context if needed. Test “this/there” follow-ups, malicious prompt, unrelated temples, absent sources, provider auth/quota, latency budget and accessible FAB label.

## F24–F28: feedback and dormant areas

**F24 Notifications.** Job: confirm meaningful user actions. Navbar bell mounts local NotificationDropdown (`Navbar.jsx:244`, `NotificationDropdown.jsx:20`); notificationService `:9–32,159–242`. Read/filter/dismiss/clear synchronize same tab and other tabs; search/empty states exist. Only actual caller wiring creates alerts; template/confirm currently emit success prematurely. Global key mixes account activity; preferences is inert; two responsive dropdown mounts share state and listeners. A04/A05/A29. **Local feedback only, not live travel updates**. Tie events to acknowledged action, scope by user, clearly label local activity; validate read sync, account switch, failed save, duplicate event IDs, responsive focus and no notifications when action fails.

**F25 Inbox (dormant).** Job if enabled: receive relevant recommendations. Modules subscribe scoped to userId, normalize timestamps, provide read/pin/archive/delete; no mounted entry, producer, rules/index deployment or bridge in repo. Error state not rendered by InboxDropdown, hover-only actions limit touch/keyboard, batch clear relies on rules. A34/A27 **not shipped/not verified**, defer. Before enabling, prove Firestore rule enforcement, auth identity switching and offline-cache behavior using emulator and staged configuration. No broad claim of a live insecure database is made.

**F26 live rail (dormant).** Job if enabled: compare journey-specific fare evidence. Modules group RailRadar results and class choices; cityStationMap covers a small city subset. Active chat estimates are separate and labeled estimated. Dormant imports/exports/class code mismatch, next-operating-date selection and week-long fare cache must be resolved before using “Live.” A24 **post-launch**, keep estimates honest now. Validate actual user journey date, quota, station/train/class identities, cache timestamp and bounded request count before any pilot.

**F27 alternate history (dormant).** Job if enabled: synthesize sourced story when wiki lacks it. Unmounted historyController imports sectioned retrieval, Groq extraction, sourceCascade and storyShaper. It does not improve current tab by existing on disk. Broad .org/domain-substring allowlist and unchecked redirect destinations are potential trust/SSRF risks if connected; current active public endpoint exposure is not established. A22/A24/A32 **defer connection**. Require strict source identity/scheme/public-address/redirect validation, bounded extraction and source partitions; test malicious retrieved instructions, broad domain lookalikes, redirects to private addresses and unsupported claims with local fixtures.

**F28 other utilities/assets/scaffolding.** MapView has optional Google Maps initialization/directions with cleanup but is unmounted; public HTML loads Maps with placeholder key (`client/public/index.html:42`). Alternate Navbar has fake notifications but is not imported by App routes; do not report those fake notifications as live. Standalone ErrorBoundary is unmounted; temple-specific boundary is active. PlacesService/curatedPlaces and queued geminiService are dormant; no admin/payment/analytics inferred. A28/A30/A32. **No launch certification**. Validate only reactivated code; remove stale scripts/imports after dependency evidence, preserve artwork and brand. Bundled asset rendering, image appropriateness and licensing remain unverified.
